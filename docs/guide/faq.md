# 常见问题

## 鼠标穿透为什么不生效?

穿透通过 Wayland 的输入区域(input region)实现:常态下只有图片矩形接收指针事件,按
<kbd>T</kbd> 后整个表面都设为空输入区,点击会穿透到下层窗口。若无效,请确认会话是真正的
Wayland 会话(`echo $WAYLAND_DISPLAY` 有值),而非 XWayland。

## 支持其它合成器吗?

本程序面向 niri / Wayland 设计;其它 Wayland 合成器需自行验证窗口置顶与键位绑定。

## 截图从哪来?

由 danklinux 默认的 `dms screenshot` 提供,默认复制到剪贴板;pinapp 通过剪贴板读取图片。

## 已知限制

- **始终置顶**:取决于合成器;niri 只会把浮动窗置于**当前工作区**的平铺窗之上,没有跨工作区的
  「始终置顶」开关。
- **无运行时移动 / 缩放 OS 窗口**:因此采用「全屏透明窗 + 输入区域」方案(有意设计,详见
  [安装](/guide/install) 页的构建说明)。
- **多贴图聚焦**:键盘快捷键(R / F / V / T / Esc)只作用于当前聚焦的最顶层贴图;目前没有标识说明
  哪张被聚焦。
- **点击穿透焦点陷阱**:进入点击穿透后整窗输入区为空,Wayland 合成器通常靠点击给焦点 —— 点击都
  穿透了,窗口可能拿不到键盘焦点,导致 <kbd>T</kbd> 切不回来。
- **守护进程生命周期**:关闭最后一张贴图时,GPUI 通常会随最后一个窗口关闭而退出;下一次
  `pinapp --pin` 会自动重新拉起。若需要严格常驻,可用 systemd 服务或离屏保活窗。
- **纯 Wayland 剪贴板**:当 arboard 读不到剪贴板时,依赖 `wl-paste`(wl-clipboard)。
- **键盘焦点**:快捷键假设贴图窗口已聚焦(新开的窗默认聚焦)。若按键无响应,先点一下图片聚焦。
